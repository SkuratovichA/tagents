## Why

Every Claude Code session on the machine starts the plugin's knowledge server through `packages/knowledge/bin/knowledge-mcp`. That script starts node to run `tagents-knowledge serve`, which prints the socket of one shared node daemon per environment and starts it when nothing answers, and then replaces itself with `nc -U` on that socket. A node `tagents-knowledge mcp` server held 29 MB by `footprint` after one search over a five-document corpus on 01.11.2026, which is the cost the shared daemon exists to pay once and not per session. The shared arrangement needs node for the start of every session and needs `nc` on the machine; a machine without `nc`, or a daemon that cannot start, gets a node server per session.

The Rust `tagents-core` already ships as a checksummed prebuilt binary and already serves `sessions`, the `tagents` MCP server and the notification service. A Rust probe that opens the bundled SQLite and runs an FTS5 match held 80 KB by `footprint`, so what a Rust server costs is its loop, its threads and its page cache, which the implementation measures (task 16.1). A session's server can be the Rust binary: one small process that joins the shared daemon, or starts it, with no node and no `nc`, and a daemon that is itself Rust.

The change also builds what the next ports reuse: the SQLite engine inside the binary, the reader of the front matter of a markdown document, and the code that finds, starts and serves a unix socket. The read verbs of `tagents-knowledge` (`index`, `search`, `show`, `list`, `usage`) and `lint` and `toc` need the same pieces, so a later change moves them cheaply.

## What Changes

- `tagents-core knowledge mcp`, `tagents-core knowledge serve` and `tagents-core knowledge join` (three new verbs, `impl: rust`, `effect: serve`, so none is a tool) run the knowledge server on stdio, the shared server and the proxy that joins a session to it. `mcp` and `serve` do what `tagents-knowledge mcp` and `tagents-knowledge serve` do: the same six tools with the same answers, the same options, exit codes and texts. `join` is new: it connects its stdin and stdout to the shared server of the caller's environment, starts it when absent, and serves in its own process when none can be started.
- One index file serves both engines. The Rust server opens the `knowledge.sqlite` the node server writes and writes the one the node server reads: same tables, same tokenizer, same match expression, same weights, same snippet, same ordering with its tie-breakers, same refresh rules (modification time in milliseconds rounded down as node does, then the first 32 hex digits of the SHA-256 of the file). A machine can switch from one engine to the other at any moment and back.
- The usage store (`knowledge-usage.sqlite`) is read and written by the Rust server in the format the node server uses, so a read recorded by either engine is counted by the report of both.
- SQLite is compiled into the binary (`rusqlite` with `bundled`), so the three release targets run one SQLite with FTS5 and no system library. The release workflow installs `musl-tools` for the musl target, because the C compiler it finds is the one the bundled SQLite is built with.
- The front matter is read by `saphyr` (YAML 1.2), converted to the values the `yaml` package gives the node reader, and every rule of `doc.ts` is applied to them: which fields are refused, how a legacy document maps, how sections are cut.
- The shared server of the Rust binary listens on a socket of the same scheme as node's (`knowledge-<12 hex>.sock` in `tagents-<uid>` under the temporary directory) with its own key, so a Rust server and a node server in one environment are two servers on two sockets and never meet on one.
- The installer's `tagents-knowledge` command runs `tagents-core knowledge <word>` for `serve` with any arguments and for `join` or `mcp` alone when the native binary of the checkout's version is installed, and the node program for every other argument list. A call whose only argument is `join` that does not reach the binary exits 69 at once and starts nothing. `packages/knowledge/bin/knowledge-mcp` probes `tagents-knowledge join` on empty input and replaces itself with it when the probe exits 0; on 69 (and on 2, from a wrapper of an older install) it runs the old arrangement unchanged (`serve` and `nc`, then `mcp`), and after any other code it writes one line naming the code to stderr first.
- The node opener of the index waits up to 5000 ms for a lock (`pragma busy_timeout`, as the Rust opener does), so the two programs sharing one index file do not turn each other's writes into `database is locked`.
- The texts the binary prints come from the node catalogue: a generator writes the two sentences `serve` prints (`badIdle` and `serveFailed`, English and Russian) into a committed file that the binary embeds, and another writes the node server's tool list into a second, and a check fails when either is stale. The summaries of the three verbs live in the core catalogue, where the contract generator reads them. The tool answers are English literals in both programs.
- `tests/rust-knowledge-parity.sh` (new) runs the same scenarios against the node server and the Rust server on copies of the same corpus, each reading and writing the other's index, and compares the bytes. A generated file of vectors pins every helper that exists twice.
- The workspace version is raised, and the new dependencies are listed with their reason and measured cost.
- The node server stays in the tree as the fallback and as the oracle of that suite. Retiring it is a later change.

## Capabilities

### New Capabilities

- `rust-knowledge`: the knowledge server as verbs of the Rust binary: what it shares with the node server (the index, the usage store, the protocol), how it differs (its own socket key, `join`), how the three verbs behave, where it knowingly differs, and how it is kept equal to the node server.

### Modified Capabilities

- `knowledge`: the shared server of one environment is one per program as well, a fault a connection survives is reported with its detail, a stack where the program has one, and the index waits for a lock another connection holds.
- `claude-code-plugin`: the `tagents-knowledge` command runs the native server for `join`, `mcp` and `serve` when the binary is installed and answers `join` with 69 when it is not, and the server entry of the plugin joins through `join` before it falls back and says why when it falls back after a failure.

## Impact

- Code: `crates/tagents-core/src/knowledge/` (new), `crates/tagents-core/src/mcp/` (the server identity and the transport become parameters), `crates/tagents-core/src/notify/options.rs` and `crates/tagents-core/src/notify/phrases.rs` (`config_dir` and `Locale` lifted into modules the knowledge code shares), `crates/tagents-core/src/node.rs` (a rounding-down modification time, `resolve`), `crates/tagents-core/src/front_door.rs` (three arms), `crates/tagents-core/src/lib.rs`, `crates/tagents-core/Cargo.toml`, `Cargo.toml` and `Cargo.lock` (dependencies, the policy note and the version), `spec/cli/tagents-core.json` (three verbs), `packages/core/src/i18n/{en,ru}.ts` (their summaries), `install.sh` (the wrapper), `packages/knowledge/bin/knowledge-mcp`, `packages/knowledge/src/db.ts` (the busy timeout), `.github/workflows/release.yml` (one step) and `.github/workflows/rust.yml`, `tests/` (the vectors, the generators, the suite, the launcher test, `tests/install.sh`).
- Documents: `docs/architecture/rust-core.md` (the server, the daemon, the dependencies, the parser policy, the known differences), `docs/guide/claude-code-plugin.md` and `packages/knowledge/README.md` (what a session starts), `CHANGELOG.md`.
- The generated contract and the skill references gain three entries, the verbs `knowledge mcp`, `knowledge serve` and `knowledge join`; no tool is added or changed, because a `serve` verb is not a tool. `plugin.json` is unchanged: the plugin still starts `knowledge-mcp`.
- A machine without a release for its version, or with no native binary, keeps the node server and the node arrangement of the launcher, and pays a shell start for the probe, which the wrapper answers with 69 without starting node. A running node daemon is not touched: it exits after its idle time.
- New dependencies: `rusqlite` (feature `bundled`, which builds the C source of SQLite), `saphyr` and `sha2`. No async runtime, and no `unsafe` in the workspace's own crates.
- Not done: the CLI verbs of `tagents-knowledge` (`index`, `search`, `show`, `list`, `usage`, `lint`, `toc`), retiring `packages/knowledge`, tagging the version this ships in (the installer falls back to node for a version without a release), a Windows build, a knowledge server without a daemon.
- The change ships in three pull requests, merged in this order: (a) the index, the search and the usage store with the vectors, the dependencies and the musl step (task groups 1 to 6); (b) the texts, the tools, the daemon, `join`, the three verbs, the suite and the documents (groups 7 to 13), the verbs last among the code; (c) the installer seam, the launcher, the measurements and the archive (groups 14 to 17). Each leaves the node arrangement working: (a) adds code no verb calls, (b) adds verbs nothing names, and (c) names them only for a binary of the checkout's version. (a) and (b) change inputs of the binary and each raise the workspace version one minor step above their merge base; (c) changes no input and raises nothing.
