## Why

`tagents-core session open`, `session prompt`, `session last`, `session list` and `session abort` are how a script or another agent drives a headless Claude Code session, and every call still starts node through the front door. `open`, `list`, `last` and `abort` are file reads and one signal, so the node start is most of their cost. `prompt` is the verb that matters: it starts `claude`, reads its stream-json output for as long as the turn lasts, and prints the outcome that an orchestrator parses and a Telegram topic shows. Serving the five verbs in Rust leaves node needed only for the plugins written in JavaScript (stage S4, which this change does not decide) until S5 retires the fallbacks.

The part that needs care is not the printing. `prompt` starts a process and cannot hand the call to node once `claude` is running: a second turn would run the same prompt twice. Everything node would have refused, rewritten or printed differently has to be decided before the spawn, and everything after the spawn has to match node's bytes without a way back. So the rule of this change is the one of `rust-plugin-verbs`, tightened where there is no hand-over left: Rust answers only the calls it can prove are byte for byte what node answers, and it hands every other call to node before it reads a file or starts a process.

Reading node's driver for this port found one defect that the port would otherwise copy or hide. The driver decodes every chunk of the child's output with `toString()`, so a multi-byte character whose bytes arrive in two reads becomes two U+FFFD in an event, in `text` and in `detail`. Russian text makes it likely, and an oracle that is nondeterministic cannot be compared with. It is fixed in node first, in its own commit with a test and a spec requirement.

## What Changes

- `session open`, `session prompt`, `session last`, `session list` and `session abort` become verbs of the Rust binary (`impl: rust` in `spec/cli/tagents-core.json`), with node's texts, exit codes, key orders and number formats, in both locales. `session` becomes a front-door group whose `run` may decline: a call that is not one of the five verbs, or whose arguments node's `parseArgs` would reject, or that falls in a documented hand-over class, is run by the node CLI before anything is read or started.
- `session prompt` starts `claude` the way the node driver does (argv, environment, working directory, process group, the `caffeinate` hold on macOS), reads its stream with a supervisor that waits on one channel and wakes at the next deadline instead of polling, and prints the same outcome kinds, the same error line and the same exit codes. `--events` writes each event line when it is read, not at the end of the turn. A signal that ends the CLI ends it by that signal and leaves the child running, which is what node does.
- Strings that cross the stream keep their UTF-16 meaning: a lone surrogate in a text, a tool input or a result payload is printed as the escape `\udXXX`, as `JSON.stringify` prints it. `json.rs` gains an exact reading mode and a `JSON.stringify` printer for its value type, and `session last` and `session prompt` use them.
- The node driver decodes the child's output as a stream (`StringDecoder`), so a character split between two reads is one character. This is a fix of node's behaviour, specified by an ADDED requirement of `headless-sessions`, and it is the first commit of the first pull request.
- `tests/rust-session-parity.sh` (new) runs each call against node and against Rust on copies of one tree, with a stub `claude` (the `fakeClaude` of `packages/core/src/testkit.ts`) and a stub `caffeinate` on `PATH`, and compares stdout, stderr, the exit code, the stub's recorded argv and environment and the state directory, and checks which program answered. Vectors written by node pin the pieces that exist twice: the argv and environment builders, the reference schema, the stream's decision tree, the printing of numbers and strings, the signal names and the reading of invalid UTF-8.
- One table-driven grammar for the options of a verb group: `plugin::parse` is generalised into `args.rs`, and `plugin` and `session` both read their options through it, so there is no second reader to pin against the first.
- The workspace version is raised by each pull request that changes an input of the binary. No dependency is added: `rustix`, `signal-hook` and `serde_json` already carry what the supervisor needs.

## Capabilities

### New Capabilities

- `rust-session`: the five session verbs as verbs of the Rust binary: what they print and do exactly as node does, which calls they hand to node, how a turn is supervised, what happens when the CLI is signalled, the single source of their texts, and how the binary is kept equal to node.

### Modified Capabilities

- `headless-sessions`: one ADDED requirement, the child's output is decoded as a stream, so a character split between two reads is one character.
- `core-front-door`: the binary serves the five session verbs besides the verbs it served, a `session` call outside them is the node CLI's, and the example of a forwarded call names a verb the node CLI still serves.

## Impact

- Code: `crates/tagents-core/src/session/` (new: the group, the five verbs, the reference reader, the argv and environment builders, the stream reader, the turn supervisor, the outcome printers, the keep-awake hold), `crates/tagents-core/src/args.rs` (new: the table-driven option grammar, `plugin::parse` generalised), `crates/tagents-core/src/plugin.rs` (its options are read through `args.rs`), `crates/tagents-core/src/json.rs` (exact reading, `stringify`), `crates/tagents-core/src/js.rs` (the UTF-16 operations the exact strings need), `crates/tagents-core/src/child.rs` (four leaf helpers become `pub(crate)`), `crates/tagents-core/src/node.rs` (the exact modification time as a double), `crates/tagents-core/src/notify/state.rs` (the `pid` column of a record), `crates/tagents-core/src/transcripts.rs` (the reply of `session last` reads exactly), `crates/tagents-core/src/front_door.rs` (one more group), `packages/core/src/claude-driver.ts` (the stream decoder), `packages/core/src/testkit.ts` (four stub options: raw writes, a grandchild, a signal to itself, a pid file), `spec/cli/tagents-core.json` (the five `impl` flags), `Cargo.toml` and `Cargo.lock` (the version).
- Tests: `tests/rust-session-parity.sh` and `tests/rust-session-parity-driver.mts` (new), `tests/rust-session-vectors.mts` and its fixtures (new), `crates/tagents-core/tests/session_vectors.rs` (new), `crates/tagents-core/tests/front_door.rs`, `packages/core/test/` (the decoder test, the `cli-spec` invariant is unchanged), `.github/workflows/rust.yml` (both `paths:` lists, the parity step, the vector regeneration step).
- Documents: `docs/architecture/rust-core.md`, the sentences elsewhere in `docs/` that say node runs these verbs, `CHANGELOG.md`.
- The generated plugin contract and the skill references do not change: the flags move verbs between programs and leave the contract alone, which `pnpm plugin:gen` and `pnpm plugin:check` show.
- A machine with no Rust binary runs the node CLI for every verb.
- Not done: the plugin host (S4), retiring the node verbs (S5), the `--input-format stream-json` mode of the driver (the CLI never uses it), serving `session` with a missing or unknown verb (node prints its usage), any change to the state hook, and the choice of a replacement for the node binary that the `PATH` of the child starts with.
- Coordinates with the change in flight, `rust-knowledge` part b, which adds a `knowledge` group to the front door. The design lists what the implementation rebases over.
- The change ships in three pull requests, each mergeable on its own with the node fallback intact because a verb is served only when its flag says `rust`. (1) This proposal and groups 1 to 7: the decoder fix in node, the pins, the shared grammar with `plugin.rs` moved onto it, the exact JSON, the state `pid`, the `session` group with `open`, `list` and `last`, the parity suite with its stub. (2) Groups 8 to 13: `prompt`, its supervisor, the events, the keep-awake hold and the scenarios of a turn. (3) Groups 14 to 16: `abort`, the documents, and the archive.
