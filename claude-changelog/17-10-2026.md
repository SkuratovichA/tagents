[20:00] The agent-state hook can now append an event stream. While `~/.claude/agent-state/events.on` exists, it appends every agent event the notify plugin wants to `events.tsv`, one line of 13 tab-separated fields per event: time, event, key, session, agent, pane, cwd, transcript, account, tool, subtype, text and TA_LABEL. The text is clipped to 240 characters. It writes nothing while the switch is off, and on a SessionStart it renames the file to `events.tsv.1` once it passes 5 MiB. `tests/events.sh` pins this with 57 checks.

[20:01] Core follows that stream (`followAgentEvents`, `createAgentFeed`). It uses one fs.watch and no polling. It rotates the file itself at 1 MiB and survives the hook's rename. The first follower in a process turns the switch on and the last one turns it off. `readLabels` reads `labels.tsv` exactly the way `label_of` does, and a test pins it against the shell function. The new `@tagents/notify` package starts with its Swift helper app, which runs one process per verb: post, withdraw, authorize, status, delivered and terminal. A click on a notice raises the right terminal and runs the notice's command.

[20:07] Plugins get three new things:
- `ctx.agents`, the event feed.
- An options file of their own at `<configDir>/plugins/<name>.yaml`, read by `loadPluginOptions`. This is the neovim layout: config.yaml enables a plugin, and the plugin's own file configures it.
- `runPluginBin`, which runs a plugin's verbs without a config.yaml registration, which is what a LaunchAgent needs.
A relative `from:` now falls back to the real config directory when the lexical path has no package, so a config committed to dotfiles can point into its own repository.

[20:19] The notify engine is in:
- It sorts events into question, permission, turn_done, subagent_done and session_end. A new prompt withdraws the session's notice.
- Every wait on the person arms a prompt-cache deadline, at 50 of 60 minutes by default. One timer sleeps at most 5 minutes and re-reads the wall clock, so a sleeping Mac cannot make the notice late.
- Titles follow the dashboard's own naming, and one tmux call tells whether the pane is already on screen.

[20:29] The macOS platform is in:
- The engine execs the helper once per post or withdraw, with a 5 s deadline.
- `build.sh --check` says whether the installed app matches the sources.
- The LaunchAgent is written, then managed with `launchctl bootstrap`, `bootout` and `print`. The `print` output is parsed against samples captured on a real Mac.

[20:46] The notify service and its verbs are in: `tagents notify run`, `install`, `uninstall`, `status` and `test`, and the package's own bin `tagents-notify`, which is what the LaunchAgent starts.
- A lock file in the state dir keeps a second service from posting every notice twice: it logs who holds the lock and exits 0. A lock from before the last boot, or naming a dead pid, is taken over.
- The options file is watched through the real directory behind a symlinked config dir, so an edit reaches the running engine without a restart.
- Stopping turns the stream switch off and releases the lock.
- `install` builds the helper app, asks for permission and writes the LaunchAgent with the PATH, locale and directories the service needs. It ends with the same report `status` prints, and with the steps for allowing notifications.
