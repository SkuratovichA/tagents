# Proposal

## Why

Registering tagents with Claude Code is the one install step still done by hand: the README and the guide hand out a block of JSON to paste into `~/.claude/settings.json`, and the same again for every other Claude config directory. Skipped, it leaves an agent invisible in the dashboard with no model column, and nothing says so. Pasted over a `settings.json` that already has hooks of its own, it either duplicates entries or overwrites what the person wrote. The installer already knows where it put the hook scripts and tagents already knows every config directory (`~/.claude`, `$CLAUDE_CONFIG_DIR` and the `config_dir` of each profile), so the step can be done for the person, provided it never edits what the person wrote.

## What Changes

- A new verb, `tagents setup [--check] [--statusline] [--config-dir DIR]... [--hooks-dir DIR]... [--quiet]`, answered by the `tagents` script itself. It writes the state hook for eight events and the status line into the `settings.json` of `~/.claude`, of `$CLAUDE_CONFIG_DIR` and of each profile's `config_dir`. It only appends: an event that already runs `tmux-agent-state.sh` is left alone, a group the person wrote is never edited, and a file with nothing to add is not written at all.
- A status line of the person's own is kept, with a message that names the command that switches (`tagents setup --statusline`), which replaces it.
- A write follows symlinks, backs the previous file up next to it, goes through a temp file and a rename, and starts over when Claude Code wrote the file meanwhile. A file that is not valid JSON, whose top level or `hooks` is not an object, or whose event is not an array, is refused and left untouched, and the other files are still done.
- `tagents setup --check` prints what would be added and writes nothing; it exits 1 while anything is missing.
- The registration is one file, `hooks/claude-settings.json`, with `@HOOKS@` where the hooks directory goes. Setup picks the hooks directory for each config directory: its own `hooks/`, else a `--hooks-dir`, else `~/.claude/hooks`.
- `install.sh` ends by running `tagents setup`: on a first install and on an update that changes `hooks/claude-settings.json`, not on every run, because the daily update would otherwise re-add entries somebody removed on purpose. It never runs it under `--check`.
- The "never used" note of `tagents --check` looks at `.claude.json` only. It used to count a `settings.json` as use, and setup now creates that file in a profile directory nobody has logged into.
- README, the getting-started, accounts and notes guides and the landing page stop handing out JSON to paste and say what `tagents setup` does instead. The notes hooks stay a manual step: `setup` registers only the state hook and the status line.

## Capabilities

### New Capabilities
- `claude-settings`: what `tagents setup` registers, which settings files it covers, how it merges and writes, when it refuses, what `--check` reports, its command line and exit codes, and when `install.sh` runs it.

### Modified Capabilities
- `claude-code-plugin`: the plugin still registers nothing, but the hook and the status line are no longer manual installation steps: `tagents setup` registers them and the installer runs it.
- `accounts`: a login's hooks are registered by `tagents setup` and may name `~/.claude/hooks`, and the "never used" note looks at `.claude.json` only.
- `cli-dispatch`: `setup` joins `update` as a bare verb the script answers itself instead of handing it to `tagents-core`.

## Impact

- Code: `lib/tagents/setup.sh` and `hooks/claude-settings.json` are new; `tagents` (module list, the `setup` verb, the `--help` header); `install.sh` (a function that runs setup after the hooks and the LaunchAgent); `lib/tagents/accounts.sh` (the "never used" test); the header comments of the two hook scripts.
- Tests: `tests/setup.sh` is new; `tests/install.sh` and `tests/config.sh` are extended; `tests/modules.sh` covers the module list, and `tests/setup.sh` (section 17) covers that the verb is the script's own and never reaches `tagents-core`.
- Contract: `setup` stays out of `tagents.cli.json`, so it is no MCP tool. `skills/tagents/references/scripts.md` quotes `tagents --help`, so it and the plugin manifest digest are regenerated by `pnpm plugin:gen`.
- Site: `site/src/content.ts` (`hooksIntro` rewritten, `hooksSummary` and `SETTINGS_JSON` removed), `site/src/components/Home.tsx`, `site/src/content.test.ts` and `Home.test.tsx`. The `site` spec of the unarchived `landing-site` change is edited in place, because it pins the `settings.json` block of the README that no longer exists.
- Docs: README `## Install`, `docs/guide/getting-started.md`, `accounts.md` and `notes.md`, and a row for `tests/setup.sh` in the suites table of `docs/development.md`.
- Dependencies: none. `jq` is already a declared dependency.
- Existing settings files keep working unchanged: the first `tagents setup` on a machine that registered the hooks by hand finds every event covered and writes nothing.
